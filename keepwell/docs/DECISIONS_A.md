# Part A Engineering Decisions (`docs/DECISIONS_A.md`)

1. **D-A01 (PostgreSQL-Only Engine with `psycopg` 3 & Real RLS):** PostgreSQL is the sole database across dev, test, and production — SQLite (`sqlite3`, `aiosqlite`) has been completely removed and the API fails fast at startup if `DATABASE_URL` is not `postgresql://`. `db/seed/load_seed.py` loads `input/docs/keepwell_schema.sql` verbatim (unmodified) with all 4 real extensions (`postgis`, `vector`, `pgcrypto`, `btree_gist`), configures `kw_app` as `LOGIN NOSUPERUSER NOBYPASSRLS`, loads all 55 CSVs (15,465 rows) via `COPY FROM STDIN`, and applies `db/migrations/001_part_a_additions.sql`. All runtime queries and RLS tests execute as `kw_app` via `psycopg` 3 (sync + `AsyncConnection`) with `SET LOCAL kw.centre_id` / `kw.role`. Locally on macOS Homebrew, `postgresql@18` is used because Homebrew's `postgis` and `pgvector` bottles target PostgreSQL 18/19; Cloud SQL targets PostgreSQL 16 (`infra/backend/setup_gcp.sh`).
2. **D-A02 (Gemini API endpoint & model env vars):** Default runtime uses the Gemini Developer API (`GOOGLE_GENAI_USE_VERTEXAI=false`) with model IDs read exclusively from `GEMINI_MODEL_AGENT` (`gemini-3.8-flash`), `GEMINI_MODEL_FAST` (`gemini-3.5-flash-lite`), `GEMINI_MODEL_PRO` (`gemini-3.1-pro-preview`), `GEMINI_MODEL_LIVE` (`gemini-3.1-flash-live-preview`), `GEMINI_MODEL_EMBED` (`gemini-embedding-2`), `GEMINI_MODEL_TTS` (`gemini-3.1-flash-tts-preview`), `GEMINI_MODEL_STT` (`gemini-3.5-transcribe`). Setting `GOOGLE_GENAI_USE_VERTEXAI=true` routes all calls to Agent Platform (Vertex AI) in `asia-south1`. When running offline or without network/quota, agents fall back gracefully to deterministic lexicon/catalogue-backed reasoning with a visible `degraded` flag.
3. **D-A03 (Dev phone hash key compatibility):** `PHONE_HASH_KEY` defaults to `keepwell-dev-hash-key` in dev/demo mode so HMAC-SHA256 phone lookups match `input/dataset/csv/household.csv` and `external_ref.csv` byte-for-byte. Production reads `PHONE_HASH_KEY` from Secret Manager.
4. **D-A04 (Additive migration `001_part_a_additions.sql`):** Adds `appliance.evidence_level` (`confirmed | probable | unverified`), `visit_debrief`, `payment_intent`, `device_token`, `outbox_event`, `fvr_14d` view, and a DB trigger enforcing consent gate prerequisites (`fix_attempt` requires gate 1 = `yes`; `diagnosis_session` with `video_on = true` requires gate 2 = `switch_to_video`). Unmodified `keepwell_schema.sql` is preserved verbatim.
5. **D-A05 (Firestore projection dual mode):** When `FIRESTORE_EMULATOR_HOST` or GCP credentials are present, `ProjectionService` writes real Firestore documents under `centres/{cid}/...` and `households/{hid}/...`. In local standalone mode without the Firebase emulator, it writes to an in-memory projection store that mirrors the exact Firestore document paths and is inspectable via tests and `/v1/admin/projection/rebuild`.
6. **D-A06 (Python version compatibility):** Codebase targets Python 3.12 in Docker/Cloud Run (`infra/backend/Dockerfile`), while using `from __future__ import annotations` and standard typing so it also executes cleanly under the host's Python 3.9 `.venv`.
7. **D-A07 (Old prototype isolation):** Legacy `keepwell/app/` prototype files are left untouched on `part-a/agent-core` to avoid git churn; all Part A code lives strictly in the contract-owned folders (`db/`, `services/`, `kb/`, `analytics/`, `evals/`, `infra/backend/`, `.agents/part-a/`, `docs/`).
